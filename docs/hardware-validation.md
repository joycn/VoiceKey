# Voice PE 实机验收

目前无设备，下列步骤尚未执行。先完成主机入口实验，再逐级接入硬件；每一步保留环境、原始数据和结果。

## 设备准备与恢复

1. 确认 Voice PE PCB 版本、Flash/PSRAM 配置，核对官方原理图 USB-C D+/D− 到 ESP32-S3 的实际通路及板上切换器状态。不能把 USB Serial/JTAG 枚举等同于自定义 UAC 可工作。
2. 确认可恢复原 ESP 固件，优先在改写前备份；保留 XMOS 版本。这个工程不会升级 XMOS，不能通过给它写新镜像来掩盖初始化失败。
3. 根据官方板级说明确认 ROM 下载模式操作（通常涉及 GPIO0/BOOT 与复位），记录这块实物上的方法后再刷写。不烧 eFuse。
4. 正常固件占用内部 USB PHY 用于 OTG，不能假设 USB Serial/JTAG 同时可用。诊断采用 UART0；调试接线不属于日常单 USB 使用要求。
5. 对明确识别的设备串口执行 `./scripts/build.sh -p /dev/cu.<实际设备> flash`。禁止照抄占位串口。使用生成的完整烧录参数，包括模型分区；固件没有 OTA 分区。
6. 出现故障时，使用事先确认的 ROM 下载操作，恢复原 ESP 固件或官方 Voice PE 镜像。注意官方恢复流程可能自行处理 XMOS；先阅读其行为。

## 主机入口预验证

Mac 保持唤醒、已解锁；ChatGPT 已登录并在后台运行且账号支持 Voice。授予麦克风权限，选定输入设备。

在应用的 `Settings → Voice → Voice chat hotkey` 尝试配置 F18，并用现有键盘/HID 验证。记录应用版本、账号功能可用性、绑定是否成功、前台/后台表现、会话已开启时再次触发的行为。不要先安装第三方常驻工具来绕过失败而仍宣称无需辅助程序。

可在触发后 0.5、1、1.5 秒开始说相同测试句，记录句首保留情况。这些只是实验档位，不是产品已批准的延迟门槛。设备灯效不作为应用已收音的计时起点。

## P0：PCM 与板级控制

记录启动日志中的 XMOS 版本、通道读回、PSRAM 大小与模型信息。默认配置 channel 0 = AGC，channel 1 = NS；默认选 channel 0 的 Q31 高位转换为 s16，USB 和检测共用同一 PCM。

GPIO10 固定低电平提供静音参考，功放关闭；没有从 Mac 扬声器获取 AEC 参考。

确认 BCLK/WS/DIN 时序、左右通道顺序、符号和有效位宽。录制本地样本，检查直流、削波、异常音量；格式未经录音验证前不要通过提高增益掩盖错误。没有 PCM 时 UAC 输出静音，黄灯提示错误。

## P1–P2：USB 麦克风与复合设备

通过一条数据线连接，确认 macOS 同时出现 UAC2 麦克风和 HID keyboard，录音格式为 16 kHz/16-bit/mono。设备 product 名为 VoiceKey Microphone，HID interface 名为 VoiceKey；系统显示名称可能取 product 而非 interface，需记录实测。

用 QuickTime、Audacity 或其他录音软件记录原始 WAV。检查静音、恢复、录音停止后再开启、USB 暂停/恢复和拔插。始终保持同一设备身份，唤醒不重新枚举；重连后可能需要主机重新选设备。

默认 VID 0xCAFE / PID 0x4014 仅为开发测试值，不能作为量产 USB 身份。验证实际总电流与 USB suspend 电流；本原型尚未做 USB 功耗合规验证。

## P3：按钮与 F18

未静音且音频正常时按按钮，记录 F18 按下与释放。默认按下 30 ms、冷却 2000 ms、待发事件超过 200 ms 丢弃。按钮做 30 ms 去抖。测试连续点击、长按、冷却结束后重触发、按下期间静音和 USB 断连。

恢复连接后先清除按键状态，不重放离线事件。正常时 HID 每 1 ms 查询；主机不轮询、总线中断或调度延迟时不能承诺端到端严格 30 ms，需要单独测量。

## P4：本地模型与并发

先使用启动日志声明的 **Hi ESP** 验证真实模型。拔掉网络仍应本地检测，USB 连续录音不停止。测试模型处理速度、wake FIFO 丢样、USB 丢样和欠载计数。

目标词 **Hey Chat / Hello Chat** 必须有对应模型并独立验收。Hi ESP 的成功不代表目标词完成。

测试静音时已有缓存、推理正在运行、HID 已排队及按键已按下等边界。红灯应持续显示静音，静音期间输出零样本且不产生新按下；解除后不重放旧样本/触发。已经提交 USB 控制器或送达主机的极短在途音频无法撤回，需区别于设备侧待发缓存。

## P5：体验、远场与长运行

用户说完唤醒词，短暂停顿后再说请求；记录唤醒时刻、HID、应用开始收音、首句完整性。无需触碰设备或电脑。

- 在 0.5/1/2/3 米、0/45/90/180 度、自然音量下测试，记录每组成功次数/总次数与语音样本。
- 覆盖不同说话人和安静、空调、键盘、说话背景、音乐、应用播放声音。儿童相关测试由监护人安排。
- 独立记录无唤醒词负样本的观察时长、误触发次数/小时，以及首句完整率与延迟分布。
- 长录音建议先跑 30 分钟，再跑 8 小时；记录丢样、欠载、堆内存和可听异常。这是测试建议时长，非已确认的验收门槛。
- 对比耳机与 Mac/外接/蓝牙扬声器；测试应用播放时用户在 2–3 米打断、输出重识别和重复唤醒。
- 发现回声问题时先定位，USB OUT 并不自动获得其他音箱的参考信号。

当前“稳定、可用、3 米目标”的数值阈值尚未确定，只有完整原始数据和明确通过标准才能判定产品验收，不能把一次演示成功写成可靠性结果。
