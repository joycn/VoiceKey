# 目标唤醒词接入状态

截至 2026-09-07，工程已集成 ESP-SR 2.2.0 内置 `wn9_hiesp`，用于验证设备内本地推理链路。仓库没有 Hey Chat / Hello Chat 对应的 WakeNet 模型；这项开发依赖不能归类为单纯“等待接上硬件”。

## 已核对的获取途径

- [Espressif 定制流程](https://docs.espressif.com/projects/esp-sr/en/latest/esp32s3/wake_word_engine/ESP_Wake_Words_Customization.html)提供定制模型服务，需要与供应方确认数据、费用和交付。文档建议通常采用 3–6 个音节；较短的 Hey Chat 需要额外关注混淆和误触发。
- [官方 TTS 模型征集入口](https://github.com/espressif/esp-sr/issues/88)允许提出新词，但不是可在本地立即执行的训练脚本，也不保证交付时间。提交涉及公开项目信息及协议接受，应作为单独外部动作处理。
- 检查当前固定组件的模型配置并搜索官方仓库后，尚未找到可直接核验并集成的 Hey Chat / Hello Chat 产物。搜索无结果并不能证明任何地方都没有此模型。

当前不向外提交项目、不购买服务，也不把 Hi ESP 改名后宣称支持目标词。若另行采用 microWakeWord，必须同时交付其特征提取、推理运行时、兼容模型和测试，不能把 `.tflite` 文件直接交给 WakeNet。

## 供应方需求草稿（未发送）

目标平台为 ESP32-S3，ESP-IDF 5.5.2、ESP-SR 2.2.0、8 MB PSRAM。输入是 XMOS 处理后的 16 kHz、s16、单声道 PCM，直接输入 WakeNet，不重复经过 ESP-SR AFE。

首选词 Hey Chat，备选 Hello Chat；需要确认短词可行性和混淆词。请提供兼容该引擎版本的完整模型、模型标识和实际词名、授权范围、文件哈希、创建/清理接口要求、输入分块大小、内存和推理耗时基准，以及训练/独立测试条件。现场目标为正常音量 1–3 米，包含键盘、空调和桌面扬声器播放；现场准确性仍由本项目验证。

## 模型到手后的开发检查

1. 核对版本、文件完整性和授权；如果需要引擎升级，先更新锁文件并重新跑全部软件检查。
2. 使用交付方认可的打包流程生成模型分区，确认完整烧录参数包含该分区。不得直接修改 `managed_components` 内的内置模型来隐藏来源；以独立项目模型目录或受版本控制的组件覆盖接入。
3. 检查启动实际报告目标模型和词；验证 16 kHz/mono、分块大小及模型清理行为。分别测试正样本、近音负样本和静音前后的上下文清理。
4. 在 Voice PE 上记录推理耗时、FIFO、USB 连续性和声学数据；只有对应证据成立才能勾选 OpenSpec 任务 5.1。

此文档完成获取途径与接入契约的准备，不代表模型已取得或目标词已实现。
